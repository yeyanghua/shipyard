⑧ AI 故障诊断弹窗

构建失败时弹出 · 根因 + 修复建议 + 相关文档
route: 弹窗（覆盖在构建详情页上）
↑ 半透明背景遮罩（构建详情页）
🤖
AI 故障诊断
构建 #127 · user-service · order-service 失败
×
根因分析 置信度 87%
OrderServiceTest.testConcurrentInsert 在 step 3 of build 失败。日志显示 deadlock found when trying to get lock，疑似数据库行锁竞争。
📋 证据
[ERROR] Caused by: java.sql.SQLException: Lock wait timeout exceeded
at com.example.OrderDao.insert(OrderDao.java:42)
at com.example.OrderService.create(OrderService.java:78)
💡 建议修复
① 缩小事务范围 高优
将 OrderService.create() 的事务从 Service 层下沉到 Dao 层单个 insert 操作
② 加超时重试 中
用 Spring Retry 在 dao 层对 LockTimeout 异常重试 2 次，间隔 100ms
③ 加索引 低
order 表 user_id 字段加索引减少行锁范围
📚 相关文档
MySQL 锁等待 · Spring 事务边界 · OrderService 提交历史(最近 5 次都成功)
🤖 基于 build_log.content + 历史 5 次成功部署分析
忽略 采纳建议 ① 打开文件
设计要点 模态弹窗覆盖在构建详情页上。**4 个区块**：根因(红) → 证据(黑) → 建议(灰) → 相关文档(蓝)。颜色编码让用户 5 秒抓住重点。
1置信度徽章 LLM 返回 confidence(0-1)，> 0.8 高 / 0.5-0.8 中 / < 0.5 低。**让用户决定是否采纳**——不假装 AI 永远对。
2证据 + 建议分离 证据来自 build_log 原文（不加工），让用户能验证 AI 没瞎说。**这是建立信任的关键**。
3建议带优先级 ①②③ 标"高优/中/低"——用户从高优开始看。
4"采纳建议 ①"按钮 点了后 → master 在项目仓库创建 fix 分支 + 改代码 + 提 MR。**一键闭环**。"打开文件"是只跳 IDE 看。
