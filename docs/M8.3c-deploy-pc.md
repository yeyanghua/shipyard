**关键设计**:
- **shipyard 调 worker**: 走 `http://192.168.91.138:30080` (NodePort, 跨网段)
- **worker 调 shipyard**: 走 `http://192.168.10.29:8080` (PC 主机内网 IP, 跨网段 + 防火墙)
- **worker 调 k8s API**: 走 in-cluster ServiceAccount (无 kubeconfig, kubelet 自动注入)

## 故障排查

### 1. kubectl apply 后 pod 卡 `ImagePullBackOff`
- 镜像没传到 k8s master, 重跑 Step 5 (ctr import)
- 或 imagePullPolicy: Never 跟 image name 拼错 (检查 deployment.yaml line 231)

### 2. pod `ErrImagePull` 报 `manifest for shipyard-worker:dev not found`
- image 名字拼错, 检查 docker images 输出
- master 上 ctr -n k8s.io images ls 看不到 shipyard-worker:dev

### 3. pod Running 但 worker 日志报 `register business error: code=... message=...`
- `code=400 message=workerToken: 不能为空` → worker pod 缺 WORKER_TOKEN env, 检查 deployment.yaml
- `code=400 message=环境不存在: dev` → shipyard DB 没 dev env 行, 重做 Step 3
- `code=400 message=worker 不可达 cause=null` → 防火墙挡, 重跑 PC 端 netstat / 跨网段验证

### 4. curl http://192.168.91.138:30080/healthz 失败
- kubectl get svc -n shipyard 看到 NodePort 30080 没分配? 检查 deployment.yaml line 304 nodePort
- 防火墙挡 30080 端口 (在 192.168.91.138 节点 firewall-cmd --add-port=30080/tcp)

### 5. 浏览器 /workers 看不到 worker
- 强刷 Ctrl+F5 (Pinia store 缓存)
- curl http://192.168.10.29:8080/api/workers 看 shipyard DB 实际数据
- worker pod 日志: registered to shipyard workerId=... 确认 register 成功
