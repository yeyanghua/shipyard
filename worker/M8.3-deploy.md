## 0. 两种 K8sClient 模式

| 模式 | 触发条件 | 用途 | 鉴权 |
|------|----------|------|------|
| **in-cluster** | `K8S_IN_CLUSTER=true` 且 `/var/run/secrets/.../token` 存在 | **生产** — worker 跑在 k8s pod 里 | ServiceAccount token |
| **kubeconfig** | `K8S_IN_CLUSTER=false` 或 in-cluster 失败 | **本机开发** — worker 跑 Mac | `~/.kube/config` |
| **fake** | 都失败 / 主动用 fake | **单元测试 + 本机零依赖** | 无 |

3 模式自动 fallback: in-cluster → kubeconfig → fake。日志会打哪个 mode 生效。

## 2. M8.3b 部署到 k3d pod (M8.3a 之后做)

### 2.1 前提

- **本机 k3d 已经在跑** (`k3d-shipyard-server-0`, 验证: `kubectl get nodes`)
- **k3d image import 能用** (k3d v5+ 内置)

### 2.2 步骤

```bash
# 1. build worker 镜像
cd /Users/hardy/learnProject/shipyard
docker build -t shipyard-worker:dev -f worker/Dockerfile worker/

# 2. 导入镜像到 k3d (k3d 内置机制, 不需要 push 到 registry)
k3d image import shipyard-worker:dev -c shipyard

# 3. apply worker manifest (M8.1 已写, 在 k8s/dev/worker-deployment.yaml)
kubectl apply -f k8s/dev/worker-deployment.yaml

# 4. 验证 worker pod 起来
kubectl get pods -n shipyard
# 预期: shipyard-worker-xxxx-yyyy  1/1  Running

# 5. 看 worker 启动日志 (确认 in-cluster 模式生效)
kubectl logs -f -n shipyard deployment/shipyard-worker
# 预期: "K8sClient 初始化: in-cluster  {\"version\":\"v1.35.5+k3s1\",\"node\":\"k3d-shipyard-server-0\"}"

# 6. shipyard 端: worker_url 改成 k3d 集群内 service DNS
curl -X PUT http://localhost:8080/api/envs/{envId} -d '{
  "name":"dev","displayName":"开发环境",
  "k8sNamespace":"shipyard-dev",
  "workerUrl":"http://shipyard-worker.shipyard.svc.cluster.local:8888"
}'

# 7. 端到端真打
curl http://localhost:8080/api/workers/{id}/cluster/namespaces
# 返 4 个真 k3s ns (从 k3d 集群内, 跨 pod 网络)
```

### 2.3 ServiceAccount 检查

worker manifest `k8s/dev/worker-deployment.yaml` 已配:
- `ServiceAccount: shipyard-worker` (M8.1)
- `ClusterRole: shipyard-worker-readonly` (只读 namespaces/pods/deployments)
- `ClusterRoleBinding` 绑定

进 k3d pod 后, worker 自动读 `/var/run/secrets/kubernetes.io/serviceaccount/token` 鉴权。

### 2.4 k3d 镜像导入 (备选)

如果 `k3d image import` 失败 (网络/版本问题), 用本地 registry:

```bash
# 1. 起本地 registry (跟 k3d 同一 docker network)
docker run -d -p 5000:5000 --restart=always --name registry registry:2

# 2. k3d 集群创建时挂载 registry (一次性)
#    (注意: 你的 k3d 集群已经存在, 这步需要重建 k3d 集群)

# 3. 改 manifest 的 image 引用
#    image: 127.0.0.1:5000/shipyard-worker:dev
#    imagePullPolicy: Always

# 4. push + apply
docker tag shipyard-worker:dev 127.0.0.1:5000/shipyard-worker:dev
docker push 127.0.0.1:5000/shipyard-worker:dev
kubectl apply -f k8s/dev/worker-deployment.yaml
```

## 3. 已知问题 & 限制

- **M8.3a 状态**: 节点名 = "unknown" (因为本机不读 downward API, 直接拿 `~/.kube/config` 没法精确知道 worker 跑哪个节点)
  - 生产 in-cluster 模式会从 `NODE_NAME` env (k8s downward API 注入) 拿真值
- **k3d 集群资源**: 本机 k3d 是单节点,跑 coredns 时会 Pending (CPU/内存不够)。生产环境多节点就好
- **M8.4+ 才做真 deploy**: M8.3 只做读类操作 (ListNamespaces/ListPods/ListDeployments), write 类 (apply deployment yaml) 等 M8.4
